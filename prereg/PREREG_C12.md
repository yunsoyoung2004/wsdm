# C12 사전등록 — 관계 정의의 근거와 한계 실험 (작성: 2026-10-31, 실행 전)

## 지위와 이미 본 것
- 사이트 분할, v1 추출기, λ=1, 다양한 표본(seed 2026, 사이트당 100문항, 페이지당 최대 3문항)은 기존과 동일하게 고정.
- 네 집합(dev, select, confirm, 공식 Test) 모두 이전 분석에서 열람했다. 다만 **아래 조건들(확장 관계, 제거 실험, 청크, 의미 기반 검색기, 질문 바꾸기, 생성형 리더)은 어느 집합에서도 계산한 적 없다.**
- 따라서 C12는 "이미 본 사이트에서의 사전등록 2차 분석"이며, 결과는 모두 보고한다. 실행 후 설정을 바꿔 다시 돌리지 않는다.

## A. 관계 정의의 근거: 질문-정답 연결 단어는 어디에 있나 (서술 분석, 판정 없음)
- 질문의 내용어 중 정답 노드 글자에 없는 단어를 **연결 단어**라 한다(불용어 제외).
- 각 문항에서 연결 단어가 아래 위치에 나타나는지 센다: 네 규칙(행 제목·열 제목·직전 레이블·섹션 제목), 부모, 조상(3단계), 형제, 같은 행 다른 칸, 같은 열 다른 칸, 표 캡션, `dt→dd`, `label[for]`, `figcaption`·`legend`, 속성(`title`, `alt`, `aria-label`, `itemprop`, `class`, `id`, `name`), 직전 10개 노드, 페이지 어딘가, 페이지 어디에도 없음.
- 보고: 위치별 포함률, 네 규칙의 합집합 포함률, 네 규칙이 놓친 문항 중 각 위치가 추가로 덮는 비율, 연결 단어가 페이지 어디에도 없는 비율(바꿔 말하기 격차).
- 정답은 이 서술 분석에만 쓰며, 어떤 순위 함수에도 들어가지 않는다.

## B. 쓰지 않은 설명 관계의 존재율과 효과
- B1(서술): 위 확장 관계 각각이 정답 노드에 존재하는 비율.
- B2: `fusion_ext`(관계 + 캡션 + dt + label[for] + figcaption/legend + 속성) − `fusion_rel`, Recall@30. **방향 예측 없음.**

## C. 네 규칙의 제거 실험 (어느 관계가 핵심인가)
- 조건: 전체 관계, 하나씩 빼기(−행, −열, −레이블, −제목), 하나만(행, 열, 레이블, 제목), 관계+부모(64토큰).
- **C-1(주):** 전체 관계 − 각 "하나만" 조건 ≥ 0 (전체가 어느 단일 규칙보다 낫다). 판정: 네 비교 중 사이트 CI 하한이 0 미만인 비교가 없으면 통과.
- C-2: 하나씩 빼기 네 조건 중 가장 큰 손실을 내는 규칙을 보고(방향 예측 없음).

## D. 의미 기반 검색기 (BM25에 한정된 현상인가)
- 모델: `BAAI/bge-small-en-v1.5`(주), 노드 입력 최대 128토큰.
- 조건: dense_text, dense_rel(글자+자기 관계), dense_shuf(글자+무작위 남의 관계), dense_parent(글자+부모, 관계 길이로 자름).
- **D-1(주):** dense_rel − dense_shuf > 0 (Recall@30). 판정: 사이트 CI와 사이트→페이지 CI 하한 > 0, 양(+) 사이트가 더 많음.
- D-2: dense_text − bm25 (의미 검색기가 글자만으로 침묵 문제를 푸는가). 방향 예측 없음.
- D-3: 침묵 문항(BM25=0)에서 dense_text의 Recall@30을 보고.

## E. 질문이 헤더 단어를 따라 쓴 편향
- E-1(서술): 질문 내용어가 정답의 관계 문자열과 겹치는 비율(헤더 복사율).
- E-2: 정답을 보지 않는 바꾸기. 질문 내용어 중 그 페이지의 관계 어휘(모든 후보의 관계 문자열 토큰)에 있는 단어를, 페이지에 없는 WordNet 동의어로 바꾼다.
- **E-2(주):** 바꾼 질문에서 fusion_rel − fusion_shuf > 0 (Recall@30, BM25). 판정은 D-1과 같음. 의미 기반 검색기가 있으면 dense_rel − dense_shuf도 같은 기준으로 보고.
- 예측: BM25 격차는 원 질문보다 줄어든다(크기만 보고).

## F. 생성형 리더 (선택, 시간이 되면)
- `Qwen/Qwen2.5-1.5B-Instruct`, 탐욕적 디코딩, 최대 16토큰, 64단어 문맥.
- F-1: fusion_rel − bm25, 답변 F1 > 0. 판정은 D-1과 같음.

## G. 일반 청킹과의 비교
- 페이지 글자를 문서 순서로 64단어 창(보폭 32)으로 자르고 BM25로 순위를 매긴다.
- **G-1(주):** 같은 64단어 예산에서 노드+관계 묶기(fusion_rel) − 청크 상위 1개, 정답 문자열 포함률(ans∈ctx) > 0. 판정은 D-1과 같음.
- G-2(보조): 리더를 켜면 답변 F1도 같은 비교로 보고.

## H. 관계 종류별 독립 비교 (구조 쪽 하나씩, 의미 쪽 하나씩)
- 구조 관계(DOM 표준, 노드 트리): 부모, 조부모(조상 2단계), 직전 형제, 직후 형제, 문서 순서상 직전 노드, 직후 노드, 태그 경로(조상 요소 이름). 자식·자손은 노드 글자에 이미 포함되므로 따로 두지 않는다.
- 의미 관계(HTML 표준, 요소 의미): 행 헤더, 열 헤더, 직전 레이블, 섹션 제목(이상 위치로 근사), `dt→dd`, `label[for]`, 표 캡션, 속성(`title`, `alt`, `aria-label`, `itemprop`)(이상 태그·속성으로 직접).
- 각 종류를 **혼자** 붙이고, 모두 16토큰으로 자른다. 같은 종류를 무작위 다른 노드에서 가져온 조건(fusion_shuf와 같은 기증 노드)과 비교한다.
- 보고: 종류별 정답 노드 존재율, Recall@30(자기 것, 남의 것), 자기−남의 차이와 사이트 CI, 그 관계가 정답 노드에 있는 문항만의 차이.
- 추가 구조 조건: 부모·형제에서 그 노드의 의미 관계 토큰을 모두 지운 것(s_parent_minus_sem, s_siblings_minus_sem). "부모가 강한 건 의미 관계가 섞여서인가"를 가르기 위한 조건이다.
- 겹침: 정답 노드에서 레이블⊂직전 형제, 행 헤더⊂부모, 섹션 제목⊂직전 노드의 토큰 포함률.
- **H-1(주):** 의미 관계 중 존재율 10% 이상인 종류의 "자기−남의 것"(존재 문항 기준) 중앙값이, 구조 관계의 같은 값 중앙값보다 크다. 종류별 판정은 하지 않고(존재율이 매우 다름) 전부 보고한다.

## 해석 규칙
- D-1 통과 → "자기 관계 효과는 BM25에 한정되지 않는다." 실패 → 효과를 단어 기반 검색기로 한정해 보고.
- E-2 통과 → "효과가 질문의 헤더 단어 복사만으로 설명되지 않는다." 실패 → 데이터셋 편향을 한계의 핵심으로 보고.
- A, B, C는 관계 정의의 근거와 한계로 논문에 보고한다.
- 다중 비교: C-1의 네 비교에 Holm 보정, 주 가설(C-1, D-1, E-2, G-1)은 각각 독립 판정.

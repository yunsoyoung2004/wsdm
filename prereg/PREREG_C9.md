# C9 사전등록 — E2 답변 정확도 + E3-S 표본 강건성 (작성: 2026-10-31, 실행 전)

## 지위
C8과 같이 **사전등록된 2차 분석**. 평가 사이트(dev·select·confirm)는 이미 열람했음을 논문에 명시.

## E3-S: 표본 추출 강건성 (`c8_robust.py --diverse`)
지금까지는 사이트별 CSV 순서상 처음 100문항(사이트당 25~30페이지, 같은 질문의 바꿔 말하기 다수)을 사용했다.
- **다양한 표본:** 페이지를 고정 seed(2026)로 무작위 추출, 페이지당 최대 3문항, 사이트당 100문항
- **2단계 부트스트랩:** 사이트를 재표집하고, 뽑힌 사이트 안에서 페이지를 다시 재표집 → `pageCI`
- 판정: R1(H1, 무작위 동점)이 다양한 표본에서도 site CI와 page CI 하한 모두 > 0 이면 "표본 추출 방식과 바꿔 말하기 군집에 강건"

## E2: 실제 답변 정확도 (`c9_qa.py`)
- **리더:** `deepset/roberta-base-squad2` 그대로 사용 (미세조정 없음 → 학습 누출 없음). 항상 답을 출력(null 금지)
- **문맥:** 각 검색기의 상위 노드를 단어 예산 **64 / 256**에 채움. 서로 포함 관계인 노드는 건너뜀(같은 텍스트 반복 방지). 동점은 고정 seed 무작위
- **검색기:** bm25 · fusion_rel · fusion_shuf(대조군) · fusion_parent_64(C8의 가장 강한 baseline) · oracle_gold(정답 노드만 = 리더 상한)
- **정답:** 공식 WebSRC answer. SQuAD 방식 정규화로 EM/F1. yes/no 답변은 추출 불가이므로 제외하고 개수 보고
- **표본:** 다양한 표본(위와 동일)

| ID | 비교 (예산별, F1과 EM) | 기대 |
|---|---|---|
| **Q1 (주)** | fusion_rel − bm25 | > 0 |
| Q2 | fusion_rel − fusion_shuf | > 0 |
| Q3 | fusion_rel − fusion_parent_64 | 보고만 (C8에서 검색은 구분되지 않음) |

판정: Q1의 F1이 site CI와 page CI 하한 모두 > 0, 그리고 양(+) 사이트가 더 많음.

## 해석 규칙
- Q1 통과 → "검색 개선이 실제 답변 정확도 개선으로 이어진다" (주장-평가 일치)
- Q1이 64단어에서만 통과 → "적은 예산에서의 효율"로 보고 (C8 K 곡선과 일치)
- Q1 실패 → 검색 개선이 리더 단계에서 상쇄된다고 보고. 원인 분석으로 gold∈ctx와 ans∈ctx를 함께 제시
- 리더의 절대 EM은 WebSRC 최고 성능과 비교 대상이 아님(구조 정보 없는 범용 리더). **상대 비교만 주장**
